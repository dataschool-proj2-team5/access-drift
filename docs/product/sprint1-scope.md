## 1. Sprint 1 목표

Sprint 1의 목표는 보안 담당자가 리스크 카드에서 잔존 접근권한과 접근 경로를 확인하고, AI 조치 권고안을 조회할 수 있는 최소 흐름을 구현하는 것이다.

S1은 "탐지 결과를 만들고 보여주는 것"에 집중한다. Jira 실제 발행, 조치 이력 추적, 감사 로그 관리는 S1 범위에 포함하지 않는다.

## 4. 팀별 S1 목표

### DE

**목표:** PoC보다 확장된 합성 데이터를 기준으로 Landing → Bronze → Silver까지 재현 가능하고 검증 가능한 데이터 기반을 제공한다.

**주요 산출물**
- S1 대표 리스크 케이스를 포함한 확장 합성 데이터 생성/적재 기준
- Landing/Bronze/Silver 레이어별 입력/출력 검증 결과
- Bronze/Silver 스키마 계약과 변경 절차
- 재실행 시 중복/누락을 확인할 수 있는 검증 기준
- Databricks Job/Bundle 실행 및 재실행 가이드

### DS

**목표:** Silver 데이터를 입력으로 Intermediate/Gold Core를 생성하고, Risk Card 표시가 가능한 최소 결과를 만든다.

**주요 산출물**
- S1 대표 리스크 케이스별 Intermediate 결과
- Risk Card에 필요한 Gold Core 필드
- eval 정답지와 Gold 결과 비교 기준
- 대표 리스크의 입력-결과 연결 검증 결과
- AI 권고안 생성을 위한 근거 필드 정의

### PO

**목표:** Gold/Risk Card 데이터를 사용해 보안 담당자가 위험 목록과 상세 근거를 확인할 수 있는 화면을 만들고, S1 데모 흐름과 수용 기준을 확정한다.

**주요 산출물**
- Risk Overview 화면
- High-Priority list 화면
- Risk Card 상세 화면
- 접근 경로 표시 UI
- AI 조치 권고안 조회 UI
- Risk Card 필수 표시 필드
- 대표 리스크별 사용자 설명 문구
- AI 권고안 표시 기준
- Sprint 1 수용 기준

## 5. Sprint 1 완료 기준

Sprint 1은 다음 조건을 만족하면 완료로 본다.

1. PoC보다 확장된 합성 데이터를 기준으로 Databricks Landing → Bronze → Silver → Intermediate → Gold 흐름을 재실행할 수 있고, 각 레이어의 입력/출력 건수와 대표 리스크가 기대한 결과로 이어지는지 검증된다.
2. Gold 또는 Risk Card용 테이블에서 최소 1건 이상의 리스크 결과를 조회할 수 있다.
3. 각 리스크는 권한 주체, 드리프트 유형, 위험 등급, 민감 자산, 접근 경로, 잔존 접근 기간 또는 산정 기준일을 가진다.
4. eval 정답지 기준으로 S1 대표 리스크 케이스가 기대한 리스크로 매칭된다.
5. 대시보드에서 전체 현황, 우선순위 목록, 리스크 상세, AI 조치 권고안을 확인할 수 있다.
6. AI 조치 권고안은 탐지 근거 기반으로 생성되며, secret 값을 출력하거나 침해 사실을 단정하지 않는다.
7. 확인하지 못한 범위와 후속 작업이 PR 또는 스프린트 리뷰에 명시된다.

---

## 6. 확인 관점

S1 검증은 단순 실행 여부가 아니라 데이터와 화면이 기대한 의미를 담고 있는지 확인한다.

- 데이터 건수만 보지 않고 샘플 리스크의 주체, 자산, 접근 경로, 심각도가 의도와 맞는지 확인한다.
- Gold 결과가 Silver 입력 또는 eval 정답지와 어떤 key로 연결되는지 확인한다.
- AI 조치 권고안은 탐지 근거에 없는 사실을 생성하지 않고, 수동 권한 회수 절차를 포함할 수 있는지 확인한다.
- 대시보드는 보안 담당자가 1분 안에 "무엇이 남았고, 어디에 닿고, 다음 조치가 무엇인지" 말할 수 있는지 확인한다.

---

## 7. 리스크와 후속 작업

- S1은 Jira 실제 발행과 조치 상태 추적을 포함하지 않으므로, 조치 워크플로우는 S2에서 확장한다.
- 아이덴티티 기준 자산 매핑은 Backlog로 두며, S1에서는 리스크 카드 단위 접근 경로를 우선 구현한다.
- 접근 이벤트/로그는 S1 탐지 판정 기준에 포함하지 않는다. 상세 분석 참고 정보 표시는 S2에서 고려한다.
- DLT, 데이터 계약 자동 검증, UC 권한 모델 고도화는 S1 필수 완료 기준이 아니라 개발 신뢰성 향상을 위한 별도 작업으로 관리한다.
- eval은 S1 대표 케이스 검증에만 사용하며, 정밀한 precision/recall 평가는 후속 작업으로 둔다.
