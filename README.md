# Access Drift

퇴사, 부서 이동, 외주 계약 종료 이후에도 업무 도구와 클라우드 환경에 남아 있는 접근권한이 중요한 자산에 닿는지 찾아내고, 보안팀이 조치할 수 있게 보여주는 프로젝트입니다.

여기서 **Access Drift**는 관리상으로는 정리된 것처럼 보이지만 실제로는 접근권한이 남아 있는 상태를 뜻합니다.

## 문제 배경

퇴사자 계정을 비활성화하는 것만으로는 충분하지 않습니다.

- 중앙 계정 시스템과 연동되지 않은 업무 도구에는 내부 권한이 별도로 남을 수 있습니다.
- 퇴사자나 이동자가 만든 자동화용 접근 키, 프로그램 계정, 배포 권한은 사람 계정과 별개로 계속 살아 있을 수 있습니다.

이 권한이 고객 데이터, 코드 저장소, 클라우드 저장소, 배포 기능에 닿는다면 단순 관리 누락이 아니라 실제 접근경로가 됩니다.

## 대표 시나리오

1. 업무 도구 권한 잔존  
   퇴사자 회사 계정은 비활성화됐지만, 별도 협업 도구 안에 프로젝트나 데이터 접근권한이 남아 있는 경우

2. 자동화 접근 열쇠 잔존  
   담당자가 퇴사하거나 팀을 이동했지만, 그 사람이 만든 자동화용 프로그램 계정이 코드 저장소, 클라우드 저장소, 배포 기능에 접근 가능한 경우

## 예상 데모 흐름

가상 데모: <https://access-drift-poc.vercel.app/>

초기 데모는 다음 흐름을 기준으로 검토합니다.

1. 대시보드 접속
2. 위험 카드(Risk Card) 확인
3. 남아 있는 권한, 닿는 자산, 담당자와 조치 방향 확인
4. 담당자 확인 요청 메시지 또는 조치 요청서 초안 생성

## 초기 범위

우선 검토하는 범위:

- 잔존 접근권한 탐지 흐름
- 권한이 민감 자산에 닿는지 보여주는 위험 카드
- 담당자 확인 요청 메시지와 조치 요청서 초안 생성

현재 범위에서 제외하는 것:

- 회사 전체 자산관리 시스템
- 모든 보안 이상행위를 탐지하는 통합 모니터링 시스템
- 사람 승인 없이 자동으로 권한을 제거하는 시스템

## 성공 기준

데모를 본 사람이 1분 안에 다음 3가지를 말할 수 있어야 합니다.

1. 어떤 권한이 남아 있는가
2. 그 권한이 어떤 중요한 자산에 닿는가
3. 다음 조치가 무엇인가
